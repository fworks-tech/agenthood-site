# Agenthood 4.0.0 and the Week's Releases

**Date:** November 17, 2026
**Author:** Agenthood Team

We shipped Agenthood 4.0.0 this week, along with five smaller releases. The major version is mostly about skills: how they are discovered, authorized, composed, measured, and traced. It also adds per-repo agent instructions, a multimodal provider interface, and a workflow engine for chains. Below is what changed and what to check before upgrading.

## Agenthood 4.0.0

Agenthood 4.0.0 is a breaking release. Two changes need attention: `allowed-tools` from `SKILL.md` is now enforced at call time, and the no-op span API has been removed from `Tracer`. The rest of the release builds out the skill lifecycle and the workflow and tracing layers around it.

### Skills: discovery, metadata, and activation
- **Activation paths:** Skills can activate through one tool, slash commands, and structured blocks. Activations are deduplicated, skill context is protected, and activation state is restored on resume.
- **Frontmatter:** Added `compatibility`, `hidden`, and `router` fields, plus `metadata.version` with semver validation. Conditions, priority, fallback, and model-invocation opt-out are parsed from skill definitions.
- **Catalog and namespaces:** Skills can be resolved through registry namespaces and `.well-known` catalogs. User-scope skills resolve through XDG data paths, and the catalog is formatted, filtered, and ordered per provider.
- **Gating:** Skills are gated on the model, tools, and dependencies available in the current environment. Declared tools that match no registered tool are ignored.
- **Discovery performance:** Parsed skill metadata is cached and the discovery scan is bounded. Successful script output can be cached behind an opt-in switch.
- **Compaction and nesting:** Compaction-replay is honored, and nested invocation remains safe.
- **New skill:** Added the web-research skill from deepagents.

### Skills: authorization and isolation
- **Script runs:** Script execution is authorized by activation, and untrusted skills are isolated. Two authorization gaps in the script runner were closed.
- **Allowed tools:** `allowed-tools` from `SKILL.md` is enforced at call time. This is a breaking change; verification now fails on allowed-tools names Agenthood does not know.
- **Bundled scripts:** Scripts run with real runtimes, pinned one-offs, and capped output. One-off arguments and script output are bounded, and remote sources are cloned into a unique directory.
- **Subagents:** A skill can be delegated to an isolated subagent context.
- **Hardening:** Activation notices are escaped before they enter the block. The compatibility fallback no longer uses regex backtracking. Unicode names are normalized, mismatches warn, and collisions resolve.
- **Lockfiles:** Agenthood refuses to overwrite an unparsable member lockfile.

### Skills: cost, health, and lifecycle
- **Cost and budgets:** Skill cost is measured and ranked against use. The CLI reports skill token budgets and cross-location duplicates, and shows activation history.
- **Health:** Skill health and activation health are measured. Outdated copies are detected and can roll back to a version.
- **Interface contract:** Script interfaces are linted and the execution contract is documented.
- **License:** License is validated as SPDX, and a `license` command was added.
- **Scopes:** The scopes of active skills are intersected.

### Workflows and chaining
- **Workflow engine:** `chains.yaml` now executes through `WorkflowEngine`.
- **Composition:** Chains can compose skills, conditions, and parallel branches.
- **Step indexing:** Chain steps are indexed so a repeated member keeps its own result.
- **CLI behavior:** A bare `workflow` remains an error instead of listing chains. Malformed files report `chains.yaml` rather than a parser dump.

### Runtime, providers, and tracing
- **Per-repo instructions:** `AGENTS.md` and `CLAUDE.md` load as per-repo agent instructions.
- **Multimodal:** Added a multimodal provider interface and an OpenAI implementation.
- **Traces:** Every ReAct step is persisted, and trajectories can be filtered by skill or tool. Step duration, run input, and the step's provider cost are recorded. One trajectory per run is kept under a shared correlation id, `--limit` applies to skill and tool trajectory listings, and the trajectory directory is capped.
- **Pruning and memory:** Retained traces are indexed once during pruning, and provenance writes are serialized across processes.
- **Cost ledger:** Cost records the provider that answered, tolerates torn lines, and rotates the ledger.
- **Tools:** Path guards compare real paths on both sides and resolve symlinked directories before allowing a path.
- **Metrics and RAG:** The metrics server binds to the configured host, and embedding concurrency is bounded.
- **Marketplace:** Plugin manifests are validated and versions synced.
- **Reasoning:** Regex metacharacters in file patterns are escaped.

### Community and member authoring
- **Third-party contract:** The third-party member authoring contract is defined.
- **Contrib report:** The contrib contract report remains opt-in.

### Release, CI, and security
- **CI prose checks:** Every pull request runs the prose style check, and every text file is checked for AI-typical punctuation. The check accepts `--!>` as an inline finding block terminator, holds the prose pass to the lines it can police, and keeps workflow YAML valid. Herald table cells escape backslashes.
- **Release notes:** Release notes are generated dash-free and deterministically. The `!` breaking marker is honored when computing the version, and a dash inherited from a commit subject is normalized.
- **Secrets:** Environment samples and ignore rules are hardened. Hooks ignore empty and placeholder secret values and block a real token beside a placeholder. Cloud tokens and debug payloads are redacted. A rotated key is kept out of tracked config.
- **CLI and docs:** Special characters are kept when applying an optimized description. Missing table values show a hyphen. Colons broken by the dash pass are repaired.

### Breaking changes and upgrade notes
| Change | What to do |
| --- | --- |
| Skill `allowed-tools` is enforced at call time | Review each `SKILL.md`; remove or correct tool names Agenthood does not know. |
| Tracer span API removed | Remove calls to the no-op span API; rely on persisted ReAct steps and trajectory filters. |

1. Audit `SKILL.md` files for `allowed-tools` entries and confirm every named tool is registered.
2. Remove any calls to the old Tracer span API.
3. Re-run workflows and inspect traces for step duration, run input, and provider cost.
4. Check skill activation history and token budgets in the CLI.

## Smaller Releases: 3.76.0 through 3.78.0

The following releases shipped between November 15 and 16. They are smaller, but two of them touch provider routing and member registration.

### 3.78.0 — OpenCode pricing from the live catalog
- **Pricing and routing:** OpenCode pricing and routing are derived from the live model catalog.
- **Scope fix:** Catalog pricing is scoped to OpenCode providers so it does not leak into other providers.

### 3.77.1 — Responses reliability
- **Reviewer bot:** Restored the reviewer bot on `gpt-5-nano` via `/v1/responses`.
- **Incomplete responses:** Incomplete responses are surfaced, and the output budget is raised.

### 3.77.0 — Host-registered members
- **Custom members:** Hosts can register custom members.

### 3.76.1 — Audit fixes
- **Repository audit:** Applied the repository audit findings.

### 3.76.0 — Skill naming and dependency hygiene
- **Skill names:** Member names drop the `the-` prefix for cross-tool compatibility.
- **Dependencies:** Cleared npm audit advisories that were blocking dependency pull requests.

## What's Next

The 4.0.0 changes point in three directions:

- **Skill distribution:** Namespaces, `.well-known` catalogs, license validation, and compatibility metadata give skills a path to be shared beyond a single repository.
- **Composable workflows:** `chains.yaml` and `WorkflowEngine` make skills building blocks for larger flows.
- **Provider-aware observability:** Live model catalogs, multimodal providers, and step-level traces make routing and cost easier to inspect.

We'll continue to document these areas as they settle, and we'll keep the upgrade notes current.
