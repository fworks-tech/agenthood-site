# Agenthood v4.4.0 and v4.3.0: Traceability, audit detail, and routing records

**Date:** November 23, 2026
**Author:** Agenthood Team

Here's what's new in v4.4.0 and v4.3.0, both dated November 19. The releases improve run traces and audit output, add a stdin path for validated routing records, and address several provenance, redaction, CI, and dependency issues.

| Release | Date | Focus |
|---|---|---|
| v4.4.0 | 2026-11-19 | Provider tracing, provenance checks, redaction fixes, CI gates |
| v4.3.0 | 2026-11-19 | Audit visibility and routing record ingestion |

## v4.4.0 — 2026-11-19

### Provider recorded in the run trace
- **Observability:** Run traces now record which provider answered the request (#1142). This makes it easier to see where a run was served when reviewing trace output.

### Provenance and redaction corrections
- **CLI:** Provenance entries that the chain never covered are now flagged (#1121), so gaps in coverage are visible rather than passing silently.
- **Core:** We stopped over-redacting URL query strings and added detection for PKCS#8 private keys (#1128, refs #1126). This reduces unnecessary redaction in URLs while broadening coverage for a common private-key format.

### CI and dependency housekeeping
- **CI:** Librarian and auditor gate warnings are retired once their checks pass (#1125). Passing checks no longer leave stale warnings behind.
- **Dependencies:** The lockfile is synced with `package.json` (#1132), keeping dependency metadata aligned.

## v4.3.0 — 2026-11-19

### Audit output includes run metrics
- **CLI:** The audit now shows run duration, cost, and token counts (#1117). These values are available in the same audit view, making it quicker to review a run's operational footprint.

### Routing records from stdin
- **CLI:** Validated routing records can be written from stdin (#1118). This supports workflows where routing records are produced by another process and piped into the CLI.

## What's Next

The two releases point in the same direction: clearer run traces, more useful audit output, and fewer silent gaps in provenance and redaction. We'll keep improving visibility across those paths while keeping the behavior grounded in the checks and records the CLI already produces.
