# Agenthood v4.5.0: MCP transports, per-server grants, and trace visibility

**Date:** November 26, 2026
**Author:** Agenthood Team

We focused v4.5.0 on teams connecting host-declared MCP servers to Agenthood. It adds stdio and HTTP transports, server-level configuration and access controls, and trace output that makes MCP servers, grants, and invocations visible. Three fixes round out the release.

## v4.5.0

### MCP client and transports

- **stdio client:** Adds a stdio client for host-declared MCP servers, with per-member scope. (#1144)
- **HTTP transport:** Adds HTTP transport for host-declared MCP servers. (#1172)
- **Tool-list caching:** Caches tool lists per server, following ADR-050. (#1174)

Hosts can declare servers over stdio or HTTP, with tool lists cached per server. Per-member scope and per-server caching make the client behavior more granular.

### MCP configuration and access

- **Per-server environment:** Stdio servers can receive their own environment variables. (#1170)
- **Per-server readOnly grants:** Restricted members can receive read-only grants on a per-server basis. (#1171)
- **Remote authentication:** Remote auth supports env-substituted headers. (#1173)

These additions make MCP setup and permissions server-specific. Environment values and read-only access can be scoped to an individual server, and remote authentication can use header values supplied through the environment.

### Trace visibility

- **MCP trace output:** Trace now shows MCP servers, grants, and invocations. (#1148)

When an MCP-backed workflow needs debugging, the trace now includes the server, grant, and invocation context in one place.

### Fixes

- **Release audit:** Applied the 4.5 audit findings. (#1181)
- **Trace robustness:** Guarded `printMcp` against malformed decision files. (#1155)
- **Tests:** Cast the `readdirSync` mock to satisfy typecheck. (#1156)

Together, these changes extend MCP support while adding server-level controls and better trace context.
