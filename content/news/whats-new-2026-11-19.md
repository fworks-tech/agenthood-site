# Agenthood 4.2.0: Audit the Decision Trail, Verify the Chain

**Date:** November 19, 2026
**Author:** Agenthood Team

We shipped four releases across two days. 4.2.0 is the headliner: the decision trail is now something you can audit in order and verify end to end, rather than a log you read and hope. The 4.1.x line came just ahead of it and mostly concerns the Opencode plugin and the skills runtime.

| Release | Date | Highlights |
| --- | --- | --- |
| v4.2.0 | 2026-11-19 | Ordered decision-trail audit with chain verification; five-minute Opencode member runs; `--limit` applied after filtering |
| v4.1.2 | 2026-11-18 | Opencode members run on Node; a project `.env` now wins |
| v4.1.1 | 2026-11-18 | Agenthood plugin ported to the Opencode v2 plugin API |
| v4.1.0 | 2026-11-18 | On-demand skill loading, cross-location dedup, legacy utility skills, AGENTS.md prompt opt-out, CI repairs |

## v4.2.0 — Auditing the Decision Trail

### An ordered, verifiable audit

- **Cli:** The audit now walks the decision trail in order and verifies the chain (#1113).

Reading a decision trail tells you what the society did. Verifying it tells you whether the record holds together. The audit command now does both: entries are examined in sequence, and the chain linking them is checked rather than assumed. When a step is out of order or the chain doesn't reconcile, you find out at audit time instead of after the fact.

### Five-minute member runs in Opencode

- **Opencode:** A member run now gets five minutes, and an environment variable override is available for runs that need a different budget (#1109).

Five minutes covers the ordinary case without letting a stuck member hang indefinitely. The env override is the escape hatch for slower workloads, so you can extend the budget per environment instead of patching the default.

### Trace limits applied after filtering

- **Trace:** `--limit` is now applied after log entries are dropped (#1111).

Previously the limit was applied before entries were filtered out, so a request for N entries could return fewer than N even when more were available. The limit now counts what you actually get.

## The 4.1.x Line — November 18

Three patches landed the day before 4.2.0. Two were Opencode bring-up; the third was a larger feature release that reshaped how skills load and how hosts control prompting.

### v4.1.2: Node runtime and project `.env` precedence

- **Opencode:** Members now run on Node, and a project's `.env` takes precedence (#1106).

Running members on Node aligns the plugin with the runtime the rest of the toolchain expects. The `.env` change means a project can set its own values without those values being overridden by ambient configuration — the closer scope wins.

### v4.1.1: Plugin ported to the v2 API

- **Opencode:** The Agenthood plugin was ported to the v2 plugin API (#1103).

This is the groundwork the other two Opencode fixes build on. Moving to the v2 API keeps the plugin on the supported surface as the host's plugin interface evolves.

### v4.1.0: Skills, runtime, and CI

**Skills**

- **Skills:** Skill bodies now load on demand at activation (#1097, refs #614).
- **Skills:** Skills are deduplicated across locations, with an opt-in merge (#1096).
- **Catalog:** We adopted the legacy utility skills and widened the public catalog (#1082).

Loading skill bodies at activation rather than up front keeps the working set small: a skill costs what it costs only once it's actually in use. Cross-location dedup addresses the practical problem of the same skill appearing in more than one place, and the merge is opt-in so existing layouts keep working until you choose to consolidate. The catalog itself grew with the legacy utility skills, now included alongside what was already public.

**Runtime**

- **Runtime:** A host can opt out of AGENTS.md prompt injection (#1100, refs #406, #1071).

Hosts that supply their own instructions can now decline the injected AGENTS.md prompt. The default is unchanged; this is an explicit opt-out for setups where the injected prompt would conflict with the host's own guidance.

**CI**

- **CI:** The automated reviewer gets real input and a deterministic gate (#1085).
- **CI:** Scheduled rituals were repaired, and the README now leads with the audit record (#1089, refs #1087).

The reviewer fix is about trustworthiness: a reviewer is only useful if it sees the same input every time and gates on a result that doesn't drift. The scheduled rituals had stopped running reliably and now do again, and the README leads with the audit record so the project's own history is the first thing a visitor sees.

## What's Next

The thread running through these four releases is verifiability. The decision trail can now be audited and checked, the CI reviewer gates deterministically, and the README opens with the audit record. That direction continues.

On the Opencode side, 4.1.1 through 4.2.0 were a sequence of bring-up fixes — the v2 API port, then the Node runtime and `.env` precedence, then the run budget. We expect to keep iterating there as the plugin settles, and we'll write each patch up as it ships.
